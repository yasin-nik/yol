## ماشین وضعیت صندلی-سانس
```
AVAILABLE -hold-> HELD -payment verified-> SOLD
HELD -expire/cancel-> AVAILABLE   (فقط اگر پرداخت در انتظار/نامشخص نباشد)
AVAILABLE/HELD <-> BLOCKED         (فقط مدیر، با Audit Log)
SOLD -refund/cancel-> وضعیت مشخص + ممیزی (هرگز حذف خاموش)
```
`SELECTED` فقط UI است.

## سناریوهای الزامی (C2)
1. پرداخت موفق بعد از انقضا: اگر صندلی آزاد است، اختصاص اتمیک؛ وگرنه سفارش «نیازمند رسیدگی» و استرداد دستی توسط مدیر (D-012).
2. پرداخت «نامشخص»: صندلی آزاد نمی‌شود؛ job استعلام دوباره.
3. رهاکردن پرداخت: آزادسازی پس از انقضا با بررسی وضعیت.
4. چند کاربر/چند تب برای یک صندلی. 5. تکرار callback/refresh.
6. اوج افتتاح فروش (تست بار پایلوت). 7. لغو/تغییر تاریخ رویداد و استرداد (استرداد دستی توسط مدیر؛ مدل داده پشتیبانی کند).
